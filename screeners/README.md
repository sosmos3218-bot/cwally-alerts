# 트루엔, 기요하라 스크리너

코스피와 코스닥 보통주를 손으로 거르는 도구다. 알림을 보내지 않고, 스케줄도 없다. 실행은 이 폴더의 CLI 뿐이다.

저장소를 찾아 보니 GRAB(성장, 순현금, 가이던스, 잉여현금흐름) 스크리너와 기요하라 다쓰로 스크리너 코드는 없었다. 데이터 출처는 추세 모니터와 같다. 재무는 OpenDART(`OPENDART_API_KEY`), 시세와 시총은 FinanceDataReader 상장 목록이고, 종목을 지정했는데 목록에 없으면 네이버 통합 시세를 쓴다.

## 파일

| 경로 | 내용 |
| --- | --- |
| `screeners/truen.json` | 트루엔(417790) 기준 숫자 |
| `screeners/kiyohara.json` | 기요하라 기준 숫자 |
| `screeners/net_cash.py` | 단순 순현금, 조정 순현금 |
| `screeners/rows.py` | OpenDART 계정 행 해석 |
| `screeners/evaluate.py` | 한 종목 통과, 탈락, 표시 |
| `screeners/opendart.py` | 실데이터 조회. 키는 출력하지 않음 |
| `screeners/fixtures/` | 테스트용 가짜 공시. 실 API 아님 |
| `screeners/tests/` | pytest |

## 트루엔 기준

모델은 코스닥 트루엔. 시총 약 714억, 별도 순현금 약 708억(현금 509억과 유동 당기손익-공정가치 금융자산 199억, 차입 없음), PER 약 6.2, PBR 약 0.62, 흑자.

통과 조건(숫자는 `truen.json`):

1. 조정 순현금 / 시총이 0.80 이상. 1에 가깝거나 더 큰 것이 핵심이다.
2. 영업이익과 순이익이 모두 흑자. TTM 이 되면 TTM, 아니면 최근 연간, 그것도 없으면 최신 누적.
3. PER 10 이하, PBR 1 이하. PER 은 TTM 또는 연간 지배순이익만 쓴다. 반기 누적만 있으면 연환산하지 않고 탈락이다.

아래는 적기만 하고 탈락시키지 않는다.

- 매출 또는 영업이익이 전년보다 줄었는지
- 배당이나 자사주 소각이 실제로 있는지(배당은 주당 현금배당, 소각은 공시 제목)
- 최대주주와 특수관계인 지분. 10% 미만이면 표시
- 금융수익이 영업이익 이상인지. 동양이엔피 2026 상반기처럼 영업이익 92억, 금융수익 240억이면 PER 가 싸 보여도 표시한다

가이던스 상향과 잉여현금흐름은 이번 통과 조건에 넣지 않았다. 가이던스는 문장 판독이라 맞다고 단정하기 어렵고, 요청한 트루엔 조건에 없다.

## 기요하라 기준

소형, 저평가, 순현금이다. 기존 구현이 없어 숫자를 `kiyohara.json` 에 두었다.

- 시총 100억 이상 3,000억 이하
- PER 10 이하, PBR 1 이하, 흑자
- 조정 순현금 / 시총 1.00 이상
- 같은 조정 순현금과 같은 가치함정 표시

트루엔 모델(비율 0.99)은 기요하라 1.00 에는 못 미친다. 대원산업 수기 예(순현금 4,469억, 시총 2,114억)는 통과한다.

## 조정 순현금

단순 순현금(예전 값, 출력에 그대로 남김):

현금및현금성자산 + 단기금융상품 + 유동 당기손익-공정가치 금융자산 + 기타유동금융자산 + 본계정 단기미수금 - 차입금 - 일반사채 - 전환사채 - 신주인수권부사채

조정(각각 이유 한 줄):

- 예수금은 뺀다. VA, PG 사업 예수금처럼 고객 정산 자금이다. 본계정과 내역이 같이 있으면 한 번만 뺀다.
- 기타금융자산 안의 단기미수금, 정산미수처럼 구분되는 정산채권은 뺀다.
- 교환사채가 사채와 따로 있으면 뺀다. 사채 내역으로 이미 들어가 있으면 한 번 더 빼지 않고 이유만 적는다.
- 리스부채는 빼지 않고 금액만 적는다.

별도 재무상태가 있으면 판정은 별도 조정 순현금을 쓴다. 연결만 있고 비지배지분이 자본의 20% 이상이면 연결 현금을 지배주주 현금으로 보지 않아 통과하지 못한다. 연결 조정 순현금에 지배 지분율을 곱한 값은 참고로만 적는다.

헥토이노베이션(214180) 픽스처는 수기 반기 점검을 재구성한 것이다. 단순 4,790억, 예수금 2,907억, 단기미수금 1,197억을 빼면 조정 686억이다. 리스 76억을 더 빼면 수기의 약 610억과 같다. 리스는 빼지 않으므로 686억이 조정값이고, 시총 1,564억보다 작아 순현금이 시총 이상인 종목으로 통과하지 않는다. 비지배지분 1,432억도 표시한다.

SNT홀딩스(036530)는 교환사채 1,026억과 비지배지분 1.12조를 표시하고 통과하지 않는다.

## 실행

테스트와 데모는 키가 필요 없다.

```bash
python3 -m pytest screeners/tests -q
python3 -m screeners selftest
python3 -m screeners truen --demo
python3 -m screeners kiyohara --demo
```

실데이터. 키 값은 치지 않는다. `--codes`, `--limit`, `--all` 중 하나가 있어야 한다. `--limit` 은 시총이 작은 순서다. `--all` 은 호출이 많아 일일 한도에 걸릴 수 있다. 응답은 `screeners/cache/` 에 남고, 결과 JSON 과 마크다운은 `screeners/output/` 에 있다. 둘 다 git 에 올리지 않는다.

```bash
python3 -m pip install -r trend_monitor/requirements.txt
OPENDART_API_KEY='발급받은키' python3 -m screeners truen --codes 417790,214180,005710
OPENDART_API_KEY='발급받은키' python3 -m screeners kiyohara --limit 50
```

기준 숫자를 바꾸려면 JSON 만 고치고 `--config` 로 넘기면 된다.

## GitHub 수동 실행

`.github/workflows/screeners.yml` 은 `workflow_dispatch` 만 있다. 스케줄과 ntfy 는 없다. 입력 `screener` 는 `both`(기본), `truen`, `kiyohara` 이다. 저장소 시크릿 `OPENDART_API_KEY` 로 코스피, 코스닥 보통주 전체를 보고, JSON 과 마크다운은 아티팩트 `screener-results` 로만 올린다. main 에 결과를 커밋하지 않는다. 로그에 키를 찍지 않는다. 단계 요약에는 통과 종목 15개까지 적는다.

종목이 많아 OpenDART 호출이 길고, 일일 한도에 걸릴 수 있다. 같은 실행에서 트루엔을 먼저 돌리고 기요하라는 캐시를 쓴다.
